# Feature: Cameras page

Added 2026-11-07 at the owner's request ("If multiple cameras are connected, user can enable/disable camera from the webpage"; "there can be an option selection feature on the website whether user want to integrate the system with a network camera or a USB camera or a CSI camera"). Owner's scope (D-034): several cameras only for RTSP, since network cameras can be in different places; one USB or one CSI camera, since those are attached to the device. This is the first step: one active camera; two network cameras at once come next.

- **Connection:** Network cameras (RTSP), USB camera (picked from the webcams found under `/sys/class/video4linux`; CSI sensors, named `vi-output`, are left out) or CSI camera (sensor 0 or 1), plus the resolution. **Save and apply** asks for confirmation, then restarts recognition with it (a service stopped on purpose stays stopped).
- **Network cameras:** add (name, `rtsp://` address, optional username and password, inserted percent-encoded), **Enable** or **Disable**, **Test** (`gst-discoverer-1.0` with a 10 s limit; shows the video format or a short reason, never the address), **Remove**. One is enabled at a time in this release; enabling one disables the others. Disabling the last one stops recognition.
- **Revert:** the previous setup is kept and **Revert to the previous setup** restores it.
- **Storage:** `data/cameras.json` (the whole setup, with RTSP logins) and `data/cameras.active` (one line `<uri> <width> <height>` that facepipe reads, overriding `FACEPIPE_URI`), both mode 0600. Pages show addresses as `rtsp://user:•••@host/…`; facepipe does not log the address of a camera chosen this way. The first visit derives the setup from `FACEPIPE_URI`.

Proof: the web self-test adds a camera with a login, checks the file mode, that the password never appears on the page, enable and disable, an invalid address, the "enable one first" rule and removal. On the Nano: test instances read `cameras.active` with no command-line camera (a video file; the USB webcam at 1280x720, 9.4 fps); the camera test reported `H.264 (High Profile)` for the owner's phone stream and "the stream could not be opened" for an address with no camera; the USB list showed the webcam and not the CSI sensor.
