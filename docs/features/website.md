# Feature: multi-page website with service control

Added 2026-11-06 at the owner's request ("Do not put everything in just one webpage, create a professional website"; "Feature to shut off or start the service from the webpage"; "the RTSP stream ... should be able to open on webpage as well"). Design agreed with Codex in a council (D-033); this is the v1.2 slice.

- **Pages:** Overview (today's numbers, recognition state, detection rate, recent activity), Live (the annotated camera as MJPEG, the same picture as the RTSP stream, paused while the tab is hidden), Attendance (any day: present, absent, unknown, evidence links, CSV, print), People (everyone enrolled, with photo count and whether they are in today), System (service control, frame and detection rates, camera, storage, last update, recent log lines).
- **Assets:** `web/layout.html` (one layout for every page, `string.Template`), `web/app.css`, `web/app.js`, `web/logo.svg`. No inline script or style, so the Content-Security-Policy is `script-src 'self'; style-src 'self'`. Python 3.6 standard library only; works offline.
- **Login:** HTTP Basic with the PBKDF2 hash in `web_auth` (unchanged). After 10 failed attempts in 15 minutes a client is refused without hashing.
- **Service control:** Start, Stop and Restart on the System page post a form with a per-process CSRF token; the server also requires the browser's `Origin` (or `Referer`) to name this host, then runs `sudo -n /bin/systemctl <action> facepipe` under the update lock, so it never collides with an automatic update. The sudoers rule `/etc/sudoers.d/facepipe-web` (installed by `deploy/install.sh`) allows exactly those three commands for `facepipe`; the website cannot stop itself. A stop is written to `data/desired`, and `deploy.sh` keeps the service stopped across updates until someone starts it.
- **Limits:** at most 24 requests at a time and 4 live viewers; request bodies up to 4 KB; clients that stop sending are dropped after 30 s; files and clips are streamed in 64 KB chunks with HTTP Range (before, a whole range was read into memory).
- **Messages:** the System page shows fixed messages chosen by a key in the URL; no request text is reflected into a page.

Proof: `python3 web.py --selftest` starts a real server on a free port and checks login, all five pages with their CSP, HTML escaping of a hostile name, Range, and that a POST is refused without `Origin`, with a wrong token, from another site, with an unknown action and when too large. On the Nano, a second instance on port 8001 with the real data served all pages, and its Restart button restarted the live service through the sudoers rule (clean stop in 3 s, active again).
